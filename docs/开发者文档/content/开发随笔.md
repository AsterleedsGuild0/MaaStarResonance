## 工具

- 调试

  [MaaXYZ/MaaDebugger](https://github.com/MaaXYZ/MaaDebugger)

  ```powershell
  # Python >= 3.9
  # 安装
  python -m pip install MaaDebugger
  # 更新
  python -m pip install MaaDebugger MaaFW --upgrade
  # 使用
  python -m MaaDebugger
  # MaaDebugger 默认使用端口 8011。你可以通过使用 --port [port] 选项来指定 MaaDebugger 运行的端口。例如，要在端口 8080 上运行 MaaDebugger
  python -m MaaDebugger --port 8080
  # 开发 MaaDebugger
  cd src
  python -m MaaDebugger
  ## 或者使用 VSCode，在项目目录中按下 F5
  ```

- 截图工具

  MaaFramework 仓库自带截图工具，位于 `tools/ImageCropper`。进入该目录后，Windows 用户推荐按照工具自身的 README 使用：

  ```powershell
  .\install.bat
  .\start.bat
  ```

  其他启动方式和参数见 MaaFramework 的 `tools/ImageCropper/README.md`。

## 依赖

oxipng 是一个基于 Rust 的图片优化工具, 需要先在本地安装 Rust 环境, 不然 Precommit Check 会报错不通过, 导致无法 commit

[Install Rust - Rust Programming Language](https://www.rust-lang.org/tools/install)

```bash
# 先确认 Rust 是否安装
rustc --version

# 如果安装了 Rust，尝试手动安装 oxipng
cargo install oxipng
```

## 本地打包与 CI 边界

从仓库根目录运行，先按[快速开始](./快速开始.md)准备依赖。以下为 Windows x64 装配参数示例，不会创建或推送 Git tag：

```powershell
uv run python scripts/build_all_platforms.py --only-os win --only-arch x86_64 --maafw-version v5.12.3 --mfaa-version v2.15.2
```

- 本地脚本下载 MaaFramework 和 SweetSmellFox/MFAAvalonia 的发行包，装配产物到 `releases/<tag>/`，不是编译 MaaFramework 源码。
- 执行会联网查询上游、重建 `releases/source_code`、清理 `releases/.build`；`--skip-deps` 仍会请求 release API，不代表离线模式。运行前确认这些目录没有需要保留的临时修改。
- `.github/workflows/install.yml` 采用另一条路径：从 MaaXYZ/MFAAvalonia 源码用 .NET 10 构建 UI，当前目标为 Windows x64/ARM64。不能把本地脚本成功等同于 CI 或其他平台运行成功。
- `scripts/install.py` 是装配步骤，会合并或覆盖根 `install/`，不是完整 GUI 构建入口。`MaaFWDocs/4.1-构建指南.md` 的 CMake 命令只用于开发框架本身。

本地打包与下节的远端发布是不同操作；验证文档改动不需要执行打包、推送 tag 或发布。

## 发布

```bash
# CI 检测到 tag 会自动进行发版
git tag v0.10.0
git push origin refs/tags/v0.10.0
```
